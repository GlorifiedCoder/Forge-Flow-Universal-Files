# Product Discovery and Requirements

1. Inspect every file in the project's `00_SOURCE_INPUTS/`, including screenshots and existing code. Use visual inspection for images and preserve original evidence.
2. Extract the problem, users, jobs, proposed value, feature inventory, screen list, workflows, roles, constraints, non-goals and success criteria.
3. Separate explicit user requirements, observations from reference images, assumptions, recommendations and open questions.
4. Do not infer hidden behavior from a screenshot alone. Ask or mark it unknown.
5. Create product brief, requirements, screen inventory, user flows, roles/permissions, and acceptance criteria before coding.
6. Prioritize Must/Should/Could and note dependencies and release risks.
7. Ask only questions that block an architectural or product-critical choice; bundle essential questions compactly.
8. Preserve language, currencies, regions, user terminology, and explicit constraints supplied in project inputs.

Output should be concrete, testable and traceable to the source input or an approved decision.
