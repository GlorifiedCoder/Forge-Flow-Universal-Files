# ZCode Task — Implement One Approved Phase

Implement only the next approved phase in `docs/04_DELIVERY/ROADMAP.md`.

1. Read project instructions, requirements, screen specs, architecture, acceptance criteria and current status.
2. Inspect Git status and current code before modifying files.
3. Break the phase into small vertical slices. Each slice should include UI, state/business logic, data/API integration, error states and tests as appropriate.
4. Implement actual behavior, not decorative buttons or fake success states.
5. Keep changes aligned with approved architecture. Record necessary deviations in the decision log.
6. Run the available Machine A formatters, analyzers and tests. Do not attempt heavyweight native Android/iOS builds on Machine A.
7. Fix failures or document them as blockers. Never suppress meaningful checks just to achieve a green result.
8. Update roadmap, implementation status, test evidence, known issues and handoff notes.
9. Report files changed, features implemented, exact commands/results, untested paths, risks and recommended next task.

Do not claim the phase is complete unless acceptance criteria are met and evidence is recorded. Do not start the next phase without approval.
